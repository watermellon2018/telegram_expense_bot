# Архив сырых SQL-миграций (до Alembic)

Эти `.sql`-файлы — **исторические** миграции схемы, применявшиеся вручную через
`psql` до перехода на Alembic (feature_113).

## Статус: устарели, не применять на новых средах

- Вся схема, которую они создают, **консолидирована** в baseline-ревизии Alembic:
  [`alembic/versions/0001_baseline.py`](../alembic/versions/0001_baseline.py).
- Новые изменения схемы делаются **только через Alembic** (см. раздел
  «Database migrations» в [CLAUDE.md](../CLAUDE.md)):
  ```bash
  alembic revision -m "описание"   # затем заполнить upgrade() через op.execute(...)
  alembic upgrade head
  ```
- Файлы оставлены как справочник по истории схемы и для аудита. **Удалять не нужно**,
  но и применять вручную на новой БД не следует — используйте `alembic upgrade head`.

## Существующая production-база

База, где эти `.sql` уже были применены, помечается базовой ревизией один раз
(без повторного создания объектов):

```bash
alembic stamp 0001_baseline
```

После этого она обновляется обычным `alembic upgrade head` (в Docker-деплое — автоматически).

## Примечание

`../utils/migration.py` — это НЕ миграция схемы, а одноразовый скрипт переноса
исторических данных из Excel в Postgres. Он к Alembic отношения не имеет.
