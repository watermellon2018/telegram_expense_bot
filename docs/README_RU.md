# Документация Telegram Expense Bot (RU)

## Назначение

Этот раздел описывает текущую архитектуру, данные, сценарии Telegram и эксплуатацию проекта.
Документы написаны как рабочая база знаний для разработки и сопровождения.

## Как читать

1. Начните с обзора архитектуры.
2. Перейдите к запуску и окружению.
3. Для фич и доработок используйте документы по Telegram-слою, БД и доменным модулям.
4. Для recommendation-системы обязательно используйте отдельный документ по модулю рекомендаций.

## Карта документов

- `01_SYSTEM_ARCHITECTURE_RU.md`  
  Общая архитектура, слои, жизненный цикл приложения, поток update.

- `02_SETUP_AND_OPERATIONS_RU.md`  
  Запуск локально и в Docker, переменные окружения, эксплуатационные команды.

- `03_TELEGRAM_INTERFACE_RU.md`  
  Меню, команды, маршрутизация handler-ов, ключевые Conversation-сценарии.

- `04_DATABASE_SCHEMA_RU.md`  
  Актуальная модель данных PostgreSQL, связи, индексы, важные миграции.

- `05_DOMAIN_LOGIC_RU.md`  
  Предметная логика: расходы, доходы, проекты, бюджеты, recurring, cashback.

- `06_RECOMMENDATION_MODULE_RU.md`  
  Полный reference по recommendation-модулю: pipeline, правила, хранилища, ограничения.

- `07_BACKGROUND_JOBS_AND_OBSERVABILITY_RU.md`  
  APScheduler-задачи, логирование, middleware, Prometheus-метрики, error flow.

- `08_TESTING_AND_CI_RU.md`  
  Локальные тесты, покрытие, структура тестового набора, GitHub Actions.

## Исторические документы

- `ARCHITECTURE_RU.md`  
  Расширенное историческое описание архитектуры (местами может дублировать новые файлы).

- `CASHBACK_MVP_RU.md`  
  Отдельный старый deep-dive по MVP-кэшбэку.

## Важные примечания

- В проекте исторически встречаются имена вроде `excel.py`, но фактическое хранилище — PostgreSQL.
- Для recommendation-функционала ориентируйтесь на модуль `recommendation/` и документ `06_RECOMMENDATION_MODULE_RU.md`.
- Порядок регистрации handler-ов критичен и описан в `03_TELEGRAM_INTERFACE_RU.md`.
