# Add Tests

Дополнение тестового покрытия для существующего кода. Реализацию **не меняем** (если только тест не вскрыл реальный баг — тогда отдельно через `/fix-bug`).

## Подготовка

1. Прочитай тестируемый код (`handlers/*`, `utils/*`) и существующие тесты в `tests/`. Используй стиль и фикстуры из `tests/conftest.py` (`mock_update`, `mock_context`, `mock_callback_query`, `test_user_id`, `test_project_id`). pytest, `asyncio_mode = auto`. БД и Telegram — моки (`AsyncMock`, `patch('module.db.fetch', ...)`), без реальных сервисов.

## Сценарии для анализа и покрытия

Для каждой функции пройди по списку и добавь тест там, где сценарий применим:

- **Happy path** — корректный вход, ожидаемая запись/ответ.
- **Права доступа** — owner / editor / viewer; отказ при недостаточной роли; не-участник проекта (`has_permission`/`require_permission` из `utils/permissions.py`). Личные данные (`project_id=None`) не пересекаются между пользователями.
- **Несуществующие сущности** — несуществующий проект/категория/расход/пользователь → корректная ошибка, а не падение.
- **Повторный запрос (идемпотентность)** — повторное действие (дубль расхода, повторное создание) обрабатывается ожидаемо. Сверься с логикой защиты от дубликатов, если она затронута.
- **Транзакционный rollback** — при ошибке в середине составной операции (`async with db.transaction()`) данные не остаются частично записанными.
- **Временные зоны** — операции с датой/месяцем учитывают таймзону (проект использует `pytz`); проверь границы месяца/дня, чтобы расход не попал в соседний период.
- **Decimal и валюты** — суммы: дробные значения, округление, отсутствие потери точности (float vs Decimal), отрицательные/нулевые суммы, очень большие значения.
- **Конкурентные операции** — параллельные изменения одного проекта/бюджета несколькими участниками; гонки в фоновых задачах (APScheduler).
- **Ошибки Telegram API** — `reply_text`/`send_*` бросает исключение (сеть, flood, прокси) → обрабатывается, не роняет handler.
- **Блокировка бота пользователем** — отправка сообщения заблокировавшему боту пользователю (`Forbidden`) — особенно в уведомлениях участникам и фоновых рассылках — не должна ломать остальную обработку.

## Завершение

Запусти `pytest` (локально может потребоваться conda-окружение `telegram_bot`). Все тесты, включая новые, проходят. Убедись, что новые тесты действительно проверяют поведение (падают при поломке логики), а не просто «зелёные».
